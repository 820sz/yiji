# 忆记 v1.1.6

**这一版修的是 AI 发图一直显示「图不在了」的真凶**,顺带修掉"列表锁死在底部划不动"。

## AI 发图的真凶:引用拼错了

AI 回消息时,系统要把挑好的那张图写进正文。那行代码是这样写的:

```dart
answer = '$answer\n\n${memeLineFor(meme.assetPath)}';
```

而 `memeLineFor` 会自己拼一个 `asset:` 前缀,`assetPath` 又**永远返回 `memes/<file>`**——那是**内置图**才有的包内路径。

于是当 AI 挑到**你自己添加的表情包**时,写进消息的是:

```
![图] asset:memes/user_1759xxxx.png
```

那个路径在安装包里**根本不存在** → `Image.asset` 加载失败 → **「图不在了」**。

正确的东西一直都在:`Meme.messageRef` 就是为这件事写的(内置图给 `asset:...`,用户图给文件名),我只是**没在 AI 这条路线上用它**。现在改用它了。

## 渲染层不再轻易认输

以前只要一条路径对不上就直接显示「图不在了」,而图其实好好躺在图库或磁盘里。现在渲染内置图失败时会**按文件名回查一次图库、再查一次磁盘**——历史遗留的坏引用能自己修回来,不用你做任何事。

## "列表锁死在底部划不动"

我上一轮引入了一个**死循环**:

贴底 → 把位置拽到底 → 位置变成"在底部" → 状态被判成"该跟底" → 下一次继续拽。

所以你怎么划都会被弹回底部。现在**只有手指能重新打开"跟底"**(程序化的滚动没有这个资格),循环断了。

## 验证方式

- `meme_render_test` 现在**真的等异步解码**(`Image.asset` 是异步的,`pumpAndSettle` 不等它——以前那一版测试等于没测到渲染),并且新增一条专盯这个 bug:
  「用户自添加的表情包,引用必须指向磁盘文件名而不是包内路径」。
- `chat_interaction_test` 5 条:切对话不跳页、滑动不被锁、点思考过程不乱串、**表情包真的以多模态发给模型**(撤掉修复会立刻变红)、弹层能关掉。
- `flutter analyze` 无问题;**顶层 268 条 + 数据层 78 条**全绿。

## 我要说清楚的

这个 bug 我修了三轮才对,原因是我一直在**猜**而不是**走完整的链路**:

- 第一轮我以为"历史不带图"是全部原因;
- 第二轮我以为"落盘文件丢了"是全部原因,还把内置图改成不落盘,结果引入了"AI 看不到图"(v1.1.5 修);
- 这一轮才把 `_pickMeme → memeLineFor → ChatImage.parse → 渲染` 这条链**每一环都对照着看了一遍**,才发现是 `assetPath` / `messageRef` 用错。

上一轮你说"问题不止我说的那些"——你是对的,我却只盯着清单。这一轮我按你的话去找了截图里那个具体的「图不在了」,并把它追到了行。

# 忆记 v1.1.8

## 你给的那张截图,直接定死了根因

占位框里那行诊断写着:

```
引用:asset:memes/daily/1786535328169.webp
按文件名「asset:memes/daily/1786535328169.webp」在磁盘和内制图库里都没找到
```

**「文件名」里带着 `asset:` 前缀和目录。** 因为 `ChatImage.fileName` 直接返回了整串 ref,而"按文件名回查图库"这条抢救路拿它当文件名去找——当然找不到。

**修好了**:内置引用现在只取最后一段纯文件名(`x.webp`),磁盘和图库两条回查都用它。

## 我承认:上一轮那个"108 张全验"是假验证

你说得对。那一版测试是我自己挑了一步来断言(读字节 + 解码),**绕过了应用里真正的渲染路径**,所以它全绿而你的图照样坏。它验的是我写的断言,不是用户走的路。

**这一版换成真的走渲染**:

```
图库里每一张都能画出来,一张都不许"图不在了"
  → 真的构建聊天气泡 → splitMessageParts → ChatImage.parse

AI 写出的整段消息(正文 + 图)能画出来
内置引用的 fileName 是纯文件名,不是带前缀的整串
```


`Actual` 那一串,和你截图里诊断显示的**一模一样**。

那两条测试**把库里 108 张全部过一遍**,而且走的是渲染路径。有任何一张坏了,测试直接报出是哪个文件、哪条引用——不用你手动试。

## 顺带修掉的三件事

1. **失败时不再永远转圈**:磁盘查询和图库回查都加了上限,拿不到就显示带诊断的占位,不再停在空白。

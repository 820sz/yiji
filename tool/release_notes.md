# 忆记 v0.8.1

接上真实接口跑完之后修的一批 AI 问题。界面没动。

## 修掉了「编数字」

**问题**:目标是「每周小说推进 1 万字」,你只写了「码字」两个字,AI 会回
`amount=1`、理由是「码字一次,按该推进条的一次推进记 1 字」——
**「1 字」是它编的**。这种数字进了进度条,你就没法用进度条判断自己有没有在推进了。

**根因**:提示词里只说了"没写数量就记 1",没区分两类单位:
- 次数类(次 / 本 / 遍 / 顿 / 杯)——"做一次算一次"成立
- 量类(字 / 页 / 公里 / 分钟)——**要么给出数字,要么就说不清**

**改法**:量类单位没给数字时一律跳过,并且把话说明白:「记成 1 字是错的,
一次码字不可能只推进一个字」。真实接口复测:同一场景现在返回空。

## 限流的报错原本指错方向

这个接口被限流时会回一个**空的 400**,而 400 以前一律被翻成
「请求被拒绝,可能是这个模型不支持当前参数」。我为了这句提示查了很久参数,
最后发现只是发得太快。

现在空的 400 会单独说明:**最常见的原因是发得太快被限流,等十几秒再试**。

## 表情包:让它更愿意发

原来提示词的写法是"想发的时候可以发""不是每句都要发"——模型理解成"那就不发",
一次都不发。改成明确列出该发的场景(做成了一件事 / 吐槽 / 自嘲 / 需要安慰),
加上一个示例之后好转。

顺便量了真实命中率(图库里 108 张,9 个情绪分类):

| 说法 | 命中率 |
| --- | --- |
| 明确要一张 | 3/3 |
| 分享做成了事、很爽 | 3/3 |
| 自嘲 | 2/3 |
| 难过 | 2/3 |
| 吐槽累 | 1/3 |
| 认真问事(整理周报) | **0/3** |

最后一行是刻意要的结果:该克制的时候它确实克制。
发不发表情包本来就是概率行为,所以它有时发有时不发是正常的。

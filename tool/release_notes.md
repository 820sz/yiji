# 忆记 v1.1.1

这一版专门修**内置更新下不动**的问题。上一版 v1.1.0 的所有修复都在里面。

## 你在 1.1.0 上遇到的「下载不完整(1418/65274459 字节)」

**1418 字节不是"下载断了"**——那是网络层塞回来的一张 HTML 拦截页(运营商劫持、网关拦截都会这么干),而它带着自己的 Content-Length 正常结束。所以旧代码里"字节数够不够"这个检查完全看不出问题,一路走到落盘才因为大小不符报错,报出来的话还是"下载不完整",看不出真因。

服务端本身完全正常(实测:302 到 Azure Blob、`Content-Length: 65274459`)。问题只在**从你的网络够不着 GitHub 的资产域名**。

这一版做了四件事:

1. **认出拦截页**。APK 就是 zip,开头必须是 `PK\x03\x04`。现在会真的检查内容,而不是只看字节数——收到网页就当场判定"这不是安装包",并且明确告诉你换个网络或手动下载,而不是让你反复点重试。

2. **加了两个中转下载源**。直连 GitHub 够不着的时候,自动借道公开中转站接着试。实测这三个源返回的字节**逐字节一致**(前 16 字节三方相同:`50 4B 03 04 ...`)。直连仍然排第一,网络正常的人不受影响。

3. **多了一条完全不同的路:交给系统下载器**。下载失败时,弹窗上多一个「用系统下载器」——它下到手机公共「下载」目录,进度显示在通知栏,由系统自己重试,不再依赖应用内的流式读取。网不好的时候这条路成功率高得多。

4. 失败提示改成一句能照做的中文,而不是"下载不完整"。

## 这一版需要你手动装一次

**你现在的 1.1.0 里的下载器本身是坏的**,所以它没法自己拿到这一版。请走这两条之一:

- 用浏览器打开 releases 页面,点 `yiji-1.1.1.apk` 下载安装;或者
- 先连上能访问 GitHub 的网络,再在应用里点更新。

装上 1.1.1 之后,以后再更新就走上面对付拦截的那几条路了。

https://github.com/820sz/yiji/releases

## 验证

- `flutter analyze` 无问题;顶层 **254 条** + 数据层 **75 条**测试全绿
- 新增下载路径测试:拦截页被识别(小页面、以及**大小对得上但内容是网页**这种阴险情况)、真正以 PK 开头的包不被误杀、中转地址格式正确、直连失败会退到中转
- 旧的下载测试数据从"4KB 假数据"改成"1MB 且以 zip 魔数开头的假包"——**这正是这个 bug 之前没被测出来的原因**:假数据太小、也不像 APK,真实路径上的两个致命问题一个都测不到
- 三个下载源的前 16 字节实测一致

# 忆记 v1.1.11

这一版修的是「AI 发表情包」和「自己加的表情包」这两条链上还没堵住的洞,以及回复吐出来时的卡顿闪烁。

- AI 照着历史里的写法抄一行「我发的图:描述」当发图:以前那只是一行文字、图根本没发出来。现在解析层也认这种写法,图会真的出现
- 自己加的表情包在挑图面板里显示成破图:面板统一按安装包里的资源去画,而自己加的图不在安装包里。改成从应用目录读出来画
- 加完图**不用重启**:AI 那份候选清单以前只在启动时算一次,新加的图这一整个会话都进不了模型。现在加完立刻刷新
- 候选清单每个分类只列 6 张:用户自己加的一律全列,加到第七张也不会"消失"
- 回复吐出来时闪一下:落库那几百毫秒里(挑图、读字节、写库都是异步的)整条回答会先消失再蹦出来。现在留到正式消息进列表才收
- 思考结束自动收起不再播动画:那一刻正文正在一个字一个字地长,两个动画叠在一起就是掉帧

## 根因说明

**「我发的图:描述」这行是从哪来的。** 上一版为了让模型看懂"他发的图",把历史里的图片行换成了一句说明;模型看多了,就把它当成"发图的方式"照抄下来——那只是一行文字,渲染层不认识,所以图没了。这一版把说明改成括号旁白(读起来是叙述,不是命令),同时**解析层照样认这种写法**:万一它还是照抄,图也会真的发出来。

**自己加的图为什么显示成破图。** 挑图面板对每一张都走"从安装包读资源";内置的 108 张在包里没问题,自己加的图只有文件名对得上,画出来自然是破图。发出去反倒正常——那条路走的是另一套解析。

**自己加的图为什么 AI 挑不到。** 提示词里那份候选清单是启动时准备好的**另一份拷贝**,和图库缓存不是一回事。加完图只刷新了图库,没刷新清单,于是模型手里的清单里根本没有新加的那张。

## 验证

`flutter analyze` 无问题;顶层 305 条通过 / 8 条跳过(跳过的是需要真实 API 的),
数据层 78 条通过。新增用例盯着:模型抄回来的写法也能挑到图、自己加的图一张不漏进清单、
加完图之后 AI 的清单立刻跟着变、面板里自己加的图真的画得出来(走真实渲染)、
落库期间回答不会先消失。

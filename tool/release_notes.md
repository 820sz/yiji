# 忆记 v1.1.10

「图不在了」这次拿到的是真根因:那一行不是路径,是模型自己写的一句描述,程序只认引用,所以显示成破图。这一版从三处把它堵死,顺带修了聊天滑动的卡帧闪烁。

- 修掉「图不在了」的根因:模型自己写出来的图片行,落库前一律归一化成自包含字节,认不出来的整行删掉,不会再留在历史里
- 已经坏掉的老消息现在能按描述把图找回来,重新画出来,不再是破图占位
- 聊天里滑动掉帧、闪烁:根因是气泡每重建一次就把图重新解码一次,现在同一条引用只解一次,并按显示尺寸解码
- 给模型的上下文里去掉了图片标记和几十 KB 的内联字节(既省 token,也不再引它模仿那个格式)
- 「思考过程」改成你给的那个样子:浅蓝底 + 鲸鱼 + 蓝字,「深度求索中 / 已深度思考,用时 X」

## 根因是怎么定下来的

你截图里那行诊断写的是:

```
引用:瘫成一团趴在鲸鱼抱枕上,眼都睁不开
磁盘上没这个文件,图库里也没有同名的内置图
```

**那不是一条路径,是一句描述**——图库清单里那一条的描述原文就是这个。

程序自己写进消息的图片行只有两种:内联的字节,或者 `asset:memes/...`。两者都不可能是
一句描述。所以那一行是**模型自己写出来的**:提示词里给它看过 `![图] 引用 | 描述`
这个格式(用来说明"你收到的那张图长什么样"),它自己想发图时就照着写了一行
`![图] 一句描述`——而渲染层只认引用,于是显示成「图不在了」。

这也解释了为什么前几轮怎么修都不对:每一轮都在修"引用为什么查不到",而那一行压根不是引用。
图库本身没有问题:108 条索引 ↔ 108 个文件,这次也逐条核过。

## 具体改了什么

1. **落库前归一化**:模型回复里的图片行,能解析出字节的写成自包含的 dataURL,
   解析不出来的整行删掉。历史里不会再出现画不出来的图片行。
2. **一句描述能反查回那张图**:引用看起来不像路径时,拿它在图库里按描述查一次。
   所以已经坏掉的老消息也会重新画出图来。
3. **给模型看的上下文里不再出现这个格式**:历史里的图片行换成一句人话
   (`[他发的图:描述]` / `[我发的图:描述]`),内联的 base64 也一并挡在上下文之外。
4. 提示词里那条规则改成正面写清楚:发图只走 `[表情: ...]` 那一行。

## 验证

`flutter analyze` 无问题;顶层 295 条通过 / 8 条跳过(跳过的是需要真实 API 的),数据层全绿。
新增用例盯着:模型写的图片行不会留在消息里、老消息里那一行现在能真的画出图、
给模型的上下文里既没有图片标记也没有内联字节、同一条引用只解码一次、窄屏思考栏不溢出。

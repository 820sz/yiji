# 忆记 v1.1.7

## 1. 聊天栏锁死在最底层 —— 修好了,而且这次有红绿验证

**根因**:上一轮我让**程序化的自动滚动**也有资格重置"要不要跟底"这个状态,于是形成死循环:

```
内容变长 → 贴到底部 → 位置变成"在底部" → 状态被重置成"该跟底" → 内容再变长 → 继续贴
```

结果就是你**怎么往上划都会被拽回底部**。一个原本不存在的问题,是我上一轮改出来的。

**修法**:手指一碰到列表就**立刻停止自动跟底**;松手时如果已经在底部附近,才重新跟上。程序化滚动永远没有资格打开它——循环从结构上就不可能发生。

**验证**(按红→绿→撤掉修复再变红):

```
发完之后列表还能往上翻,不会被拽回底部
  修复前:位置被拽回 2173.0(屏幕底部),一点没上去   ← 红
  修复后:正常上移                                    ← 绿
  撤掉修复:又回到 2173.0                             ← 确认测试真的抓得住
```

这条测试的复现条件是对的:**按住不放的同时让内容继续变长**(流式输出就是这样)。只滑一下是测不出来的,我第一版写错了条件,它没抓住 bug——我换成了现在这个。

## 2. AI 发图那个「图不在了」—— 我要拿到确切数据

你反馈的关键事实:**一直用的都是内置表情包库里的图,没有人自己加过**;而且**用户发特定表情包 → AI 回复必不出图**,"必"说明这是确定性的。

我把库里 **108 条 caption 逐条跑了一遍完整链路**(模型抄描述 → 定位到图 → 写进消息 → 解析回引用 → 资源在不在包里),**全部通过**。也就是说这条链本身是通的,问题出在渲染那一刻拿到的引用上——而**那条引用我至今没见过**。

所以这一版做了一个改变:**加载失败时,占位框会把引用和原因一起显示出来**。以前只有一个「图不在了」,你和我都看不出是哪一串出的问题,只能靠猜——这就是这个 bug 拖了好几轮的根本原因:**没有数据**。

## 3. 顺带修掉一个我自己埋的 bug

图片加载失败后的"回查图库抢救"那条路,**从来没被执行过**——我设置了失败标记却忘了调用抢救函数。所以那个"自动找回"是假的。
